# خطة: نقل الإشعارات إلى طابور مستقل

## الهدف

إرسال الإشعارات يتم الآن داخل طلب HTTP نفسه، فيتأخر الرد حين يبطئ مزوّد البريد. سننقل الإرسال إلى طابور يعمل في الخلفية، ويعود الطلب فورًا.

## الخطوات

1. إضافة جدول `notification_jobs` في `db/migrations/0042_jobs.sql` بحقول الحالة وعدد المحاولات.
2. كتابة عامل في `src/workers/notify.ts` يسحب المهام كل ثانيتين، ويعيد المحاولة ثلاث مرات بتأخير متزايد.
3. استبدال الاستدعاء المباشر في `src/api/orders.ts` بإدراج مهمة في الجدول.
4. حذف المهام المكتملة بعد سبعة أيام.

```ts
await db.insert(notificationJobs).values({ orderId, channel: "email", status: "pending" });
```

## المخاطر

- إن توقف العامل تراكمت المهام بلا تنبيه. نضيف مقياسًا لعمر أقدم مهمة معلّقة.
- الترحيل يقفل الجدول على قاعدة كبيرة؛ ننفّذه خارج ساعات الذروة.

## الاختبار

| الحالة | المتوقع |
|---|---|
| المزوّد يرد خلال 100ms | تُرسل الرسالة وتُعلَّم المهمة مكتملة |
| المزوّد معطّل | ثلاث محاولات ثم حالة `failed` |
| العامل متوقف | يرتفع مقياس عمر المهمة |
