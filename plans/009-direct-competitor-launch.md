# قرار الإطلاق بعد فحص Markdown Preview

تاريخ الفحص: 2026-07-18  
المنافس المباشر: [`pluk-inc/markdown-preview`](https://github.com/pluk-inc/markdown-preview)  
نسخة الشيفرة المفحوصة: `dc728aa` (`main`)

## الخلاصة التنفيذية

المنافس لا يتقدم على متن في عمق القراءة. يتقدم في **تجربة الوصول إلى المنتج**:
تطبيق macOS أصلي موقّع، DMG، Homebrew، Quick Look، تبويبات النظام، وتحديث تلقائي.
أما متن فيتقدم في RTL والعربية، إعدادات القراءة، عرض المصدر والتقسيم، البحث العربي،
الروابط الواردة وwikilinks، سلامة المستند، وضع الكتاب، التعليقات، الحذف الآمن، التصدير،
والعمل عبر macOS وLinux وWindows.

القرار: **لا نؤخر النشر لإضافة محرر**، ولا نعيد كتابة مصيّر متن. نطلق النسخة الحالية
بوصفها قارئًا محليًا عربيًا ومتعدد المنصات، ونبني بالتوازي مضيف macOS أصليًا حول تجربة
القراءة المثبتة.

## ما تكشفه طلبات مستخدمي المنافس

الطلبات المفتوحة البارزة لديه تشمل اختيار السمة داخل التطبيق
([#198](https://github.com/pluk-inc/markdown-preview/issues/198))، وعرض المصدر الملوّن
([#107](https://github.com/pluk-inc/markdown-preview/issues/107))، واستمرار TOC في العرض الحي
([#108](https://github.com/pluk-inc/markdown-preview/issues/108))، وتكبير الصور
([#88](https://github.com/pluk-inc/markdown-preview/issues/88)). هذه القدرات موجودة في متن؛
لذلك نسخ قائمة مزاياه سيؤخر الإطلاق بدل تقوية المنتج.

## المعمارية المعتمدة للحزمة الأصلية

لا نختار Electron، ولا نعيد كتابة الواجهة والمصيّر في Swift. البنية المستهدفة:

1. **نواة القراءة الحالية**: HTML/CSS/JavaScript والمكتبات المحلية تظل مصدر تجربة القراءة.
2. **مضيف macOS أصلي**: Swift + AppKit + WKWebView لفتح النوافذ والملفات والقوائم والتبويبات.
3. **جسر ملفات محدود**: Swift يقرأ ضمن الجذر الممنوح ويعرض أوامر صريحة للبحث والحالة والسلة؛
   لا خادم شبكي في نسخة macOS النهائية.
4. **Quick Look**: target منفصل يعيد استعمال مصيّر مبسطًا وموارد KaTeX/Mermaid المحلية.
5. **المضيف الحالي**: يبقى Node CLI للويب وLinux وWindows، ويشارك نواة العرض والاختبارات.

هذه البنية تحفظ ما يميز متن وتمنح macOS تكامل النظام. استخدام Tauri سيحل النافذة، لكنه
لن يلغي الحاجة إلى Swift لبناء Quick Look وتسجيل أنواع الملفات؛ لذلك يضيف طبقة Rust ثالثة
دون مكسب كافٍ في هذه المرحلة.

## بوابات النشر

### الآن — لا تؤخر الإعلان

- [x] دعم صيغ Markdown الشائعة، ومنها R Markdown وQuarto، مع عدم فهرسة `.txt` العام.
- [ ] تحويل PR رقم 9 من Draft بعد مراجعة علي، ثم دمجه بقراره.
- [ ] إصدار GitHub واضح للنسخة الحالية مع فيديو قصير يثبت RTL والمصدر والصحة والكتاب.
- [ ] صفحة هبوط تبيع النتيجة: «افتح ملف Markdown واقرأه كما ينبغي»، لا قائمة مزايا طويلة.

### الحزمة الأصلية — PRs مستقلة

1. استخراج نواة الواجهة من `src/index.html` إلى أصول قابلة للتضمين دون تغيير السلوك.
2. إضافة مشروع Xcode ومضيف AppKit يفتح ملفًا واحدًا داخل WKWebView مع اختبارات اتجاه.
3. نقل شجرة الملفات والبحث والحالة وإجراءات الملف إلى جسر Swift محدود.
4. إضافة Quick Look والتحقق من الصور النسبية وRTL وملف كبير.
5. بناء DMG عالمي، توقيع وnotarization، ثم auto-update وHomebrew cask.

لا يُعد التطبيق جاهزًا لاستبدال المثبت الحالي حتى ينجح نفس fixture العربي في Node ومضيف
macOS، وتعمل الميزات الأساسية دون اتصال، ولا يطلب التطبيق وصولًا أوسع من المجلد المفتوح.

## ما نؤجله عمدًا

- التحرير الحي وتحرير الجداول: يحولان متن إلى منافس لـObsidian/Notion ويضاعفان مخاطر الكتابة.
- Sentry قبل سياسة خصوصية وقرار opt-in واضح.
- Menu bar mode والزينة الأصلية قبل إتمام الفتح والتحديث وQuick Look.
- نسخ شيفرة المنافس: الرخصة MIT تسمح، لكننا نأخذ الفكرة المعمارية وننفذها بما يناسب حدود متن.
